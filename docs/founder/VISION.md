# TrackAI vision (founder, as given)

*Recorded 2026-10-07 by TrackAI-Orchestrator, unedited. Part 1 is the TrackAI Claude project description; part 2 is the founder's chat message of 2026-10-07. Edits only with the founder's OK; he will extend it.*

## 1. High-level vision (short version)

TrackAI is an AI Code Provenance, Security, Attribution and Engg Productivity Product, which is already partially done by Codex (Task 2 to Task 6.a done and merged). It is inspired by and built on top of git AI (https://github.com/git-ai-project/git-ai ; official Enterprise website at https://usegitai.com/), entire.io (https://entire.io/ ; not built on top of this, but entire.io inspires Task5) and Numbat (https://github.com/perplexityai/numbat). Numbat inspires Task 6.a.

**Provenance:** There is no task for this yet in the Roadmap. This will be Claude's first task. This task/feature will be called Attesta. This will be similar to SigStore/Rekor based signing done in SushiCorp. Details to follow.

**Security:** Coding Agent security will be provided by Numbat implementation through Task6.a. Currently only Monitor mode is supported. Later a Policy subsystem as defined in Task6.b (or a possible re-architecture based on Claude's input and learnings from agent-kit) would also be implemented.

**Attribution:** Identifying which Code is AI vs human-authored. This is done through Task2. Task13 will expand through further work on Task13. Providing useful observability metrics.

**Engineering Productivity:** Task2 + Task5. Task2 gives valuable insights on how much Code is generated by AI per Repo/PR/Model/Developer. How much rework is based on AI-generated code. What is the churn? Task5 provides Entire.io's offering, i.e. ability to visualize prompt to commit/PR (and in reverse), find similar work done before, identify non-performing Tool calls and much more.

## 2. Notes on the Tasks (founder, 2026-10-07)

- **Task2** essentially implements a version of Git AI for Teams (the enterprise version of Git AI, https://usegitai.com/for-teams). It is the real heart and soul: the actual attribution and correctness semantics, all the way from a code edit on a machine to a merged PR, with every state and step in between accounted for.
- **Task4** is infrastructure and engineering work: SSO, webhooks, plumbing, key management, queued uploads, retry management, security interfaces.
- **Task5** builds on Task2 by making telemetry data more insightful and useful, with features like similarity search.
- **The UI** is already far ahead and functional, with separate Admin and developer surfaces. Audit information is currently clubbed together in Admin.
- **Task6.a** was purely Numbat.
- **Task7** does the same as Task2 for GitLab and Bitbucket.
- **Task9** is endpoint management: managing and distributing software (the modified, forked Git AI) along with keys and future policies, managed through the server.
- **Task13** is technically an extension of Task2, covering all combinations of model, IDE, agent and desktop app (such as Claude desktop and the Codex desktop app) to capture AI code generation exhaustively.
- **Task8, Task12 and Task14** are engineering-focused: customers, deployment and production readiness.
- A lot of what is wanted from SushiCorp has already been achieved there; reuse it.
