## 2. Scope (approved)
### 2.1 Deliverables
1. **Migration** (next free number, `0017` at the time of writing) generated by `drizzle-kit generate` from additions to `schema.ts`, then guard SQL appended by hand as in 0016: tables `chain_head`, `attesta_records`, `attesta_envelopes` exactly as `tables.md` (composite `(tenant_id, …)` keys, RLS enabled with no policies, partial unique `(tenant_id, outbox_subject_id)` where not null, unique `(tenant_id, statement_digest)`, unique `(tenant_id, seq)`).
2. **Guard triggers**, all `SECURITY DEFINER` with `SET search_path = pg_catalog, public` (AGENTS.md §9 item 21):
   - `chain_head`: first row per tenant at `next_seq = 0` and `GENESIS_PREV_HASH`; `next_seq` advances by exactly 1 and only to the `record_hash` of the record at the old `next_seq`; `tenant_id` immutable; DELETE and TRUNCATE refused.
   - `attesta_records`: insert only at `chain_head.next_seq` with `prev_hash = head_hash`; `record_hash = sha256(canonical_record ‖ prev_hash)` and `statement_digest = sha256(statement_canonical)` recomputed in SQL (`pgcrypto` `digest()`; check whether the extension is already enabled by an earlier migration, otherwise enable it in this one and say so); the typed copy columns agree with the stored bytes (parse `canonical_record` with `::jsonb` only to compare, never to re-serialize); a **deferred constraint trigger** refuses COMMIT if the head was not advanced past the record; UPDATE, DELETE, TRUNCATE refused.
   - `attesta_envelopes`: one per record; the decoded payload equals the record's `statement_canonical` byte for byte; append-only.
3. **`apps/api/src/features/attesta/ledger.ts`**:
   - `chainStatement(tx, input): Promise<{ recordId, seq, recordHash, statementDigest, duplicate: boolean }>` where `input` = `{ tenantId, statementCanonical, envelope: DsseEnvelope, credentialId, keyid, signatureDer, outboxClaim?: { subjectId, claimedAt, attempts }, previousSeen: string[] }`. In one transaction the caller opened: `SELECT … FROM chain_head WHERE tenant_id = $1 FOR UPDATE` (create the head row first if absent, race-safe); if the statement digest is already chained return `duplicate: true` and still mark the outbox row done; re-read the digests of statements about the same subject and compare with `previousSeen` → `ATTESTA_LEDGER_PREVIOUS_STALE`; `recorded_at` = now in `toISOString()` form, never earlier than the previous record's; build `canonical_record` with `canonicalize`; compute `record_hash` with `computeRecordHash`; insert record and envelope; advance the head; mark the outbox row `done` only if `status = 'claimed'` with the same `claimed_at` and `attempts` → else `ATTESTA_LEDGER_CLAIM_LOST`. **No network, no signing, no builder call inside it** (AGENTS.md §9 item 18). `seq` read from `pg` as a string: convert explicitly, refuse anything outside the safe integer range.
   - Validate inputs once into a snapshot before use (Task15a lesson): `statementCanonical` must equal `canonicalize(JSON.parse(statementCanonical))`, the envelope payload must decode to the same bytes, `keyid` must equal `sha256:` + hex of the signer's SPKI as recorded, the typed columns are derived from the statement, never passed separately.
   - Errors as `AttestaLedgerError(code)` with the `errors.md` codes; database guard refusals mapped to `ATTESTA_LEDGER_HEAD_CONFLICT` (retryable) or `ATTESTA_LEDGER_GUARD_VIOLATION` (terminal).
4. **`apps/api/src/features/attesta/verify-chain.ts`**: `verifyChain(db, tenantId, { fromSeq?, toSeq? }): Promise<ChainReport>` ported from SushiCorp `core/evidence/verify.py`: a structured report `{checked, ok, breaks: [{seq, kind, detail_code}], head: {next_seq, head_hash}}`, never a bare boolean. Break kinds: the chain kinds of the source (hash mismatch, link mismatch, seq gap, seq mismatch, field mismatch, tenant mismatch, not canonical, out of order, duplicate seq, head mismatch, beyond head) mapped to `ATTESTA_VERIFY_*` codes, plus statement digest mismatch and envelope payload mismatch; signature checks against published keys use `verifyEnvelope` and report `ATTESTA_VERIFY_KEY_UNKNOWN` when the key is not supplied (anchor kinds come in A15.5). Reads stored bytes only; never re-serializes. Streams in pages, bounded memory.
5. **Tests.**
   - Unit (no database): `ledger.test.ts`, `verify-chain.test.ts` with an in-memory chain: every break kind triggered by one specific tamper; a **10 000-record tamper matrix** ported from `tests/unit/evidence/test_evidence_verify.py` (`N = 10_000`: delete, edit, swap, reorder, truncate at random positions, each detected with the right kind and seq); input validation refusals.
   - Integration through `scripts/it-db.sh`, a live verifier `t15d-ledger-live-verify.ts` with `npm run verify:task15d-ledger-live -w apps/api`:
