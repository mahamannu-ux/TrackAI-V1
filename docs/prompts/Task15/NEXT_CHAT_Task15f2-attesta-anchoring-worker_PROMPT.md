## 2. Scope (approved)
### 2.1 Decisions
1. **Migration `0018`** (next free number; verify) for `attesta_anchor_batches` and `attesta_anchors` exactly as `tables.md`, generated with `drizzle-kit generate` from `schema.ts`, guards added by hand in the 0017 style: UPDATE, DELETE and TRUNCATE raise on both tables; guard functions `SECURITY DEFINER` with `search_path = pg_catalog, pg_temp`; checks: `anchored` ⇒ `inclusion_proof` not null and `error_code` null, `failed` ⇒ `error_code` not null and proof null; `anchor_type`-specific columns (`rekor_entry_uuid` only for `rekor`, `tsa_token_b64` only for `tsa`); partial unique index on `(tenant_id, record_id, anchor_type) WHERE status = 'anchored'`; `batch_id` unique and equal to `tenant_id || ':' || seq_from || '-' || seq_to` (check constraint), `seq_from ≤ seq_to`, `leaf_count = seq_to - seq_from + 1`; an insert guard that the batch's records exist in that tenant's ledger with exactly those seqs and that each anchor's `record_id` lies inside its batch; composite tenant FKs to `attesta_records` and between the two tables; RLS on, no policies.
2. **Worker** `anchor-worker.ts`: `runAnchorPass(db, deps, opts)` with `deps = { anchor: DualAnchor; now?: () => Date }` and `opts = { maxBatch = 256, partialAfterMs = 600_000, tenantId?, limitTenants? }`. Per tenant:
   - **Plan** (one read transaction, no lock on the chain): pick the next contiguous seq range not yet in any batch, starting after the tenant's last batch; form a batch when it reaches `maxBatch` records, or when its oldest record's `recorded_at` is older than `partialAfterMs`; leaves are the 32 raw bytes of each `record_hash`; `batch_id` deterministic. A batch row already written but not fully anchored is re-planned with the **same** range and root (read it back; never re-cut).
   - **Submit** (no transaction, no lock; AGENTS.md §9 item 18): `DualAnchor.anchor(root, batchId)`.
   - **Record** (one write transaction): insert the batch row if new; when `complete`, one `anchored` row per record and type with `anchorProofJson(proofToJson(i, n, inclusionPath(leaves, i)), result)`, `rekor_entry_uuid = entryId`, `tsa_token_b64 = tokenDer.toString('base64')`; for each `failed` type one `failed` row per record with its code; `skipped` writes nothing. A unique violation on the `anchored` index (a concurrent worker won) is success, not an error.
   - Anchoring never touches `attesta_records` and never changes `record_hash`. Concurrency: two workers on one tenant are safe (`pg_try_advisory_xact_lock` keyed on the tenant in the plan step, then the unique index as the backstop); the advisory lock is never held across the network call.
   - Retry: `failed` attempts are retried on the next pass with exponential backoff derived from the count of `failed` rows for that batch and type (30 s doubling, cap 1 h); `ATTESTA_ANCHOR_LOG_KEY_NOT_PINNED` and `ATTESTA_ANCHOR_LOG_REJECTED` are terminal: the batch stops and the pass reports it (no endless retry; Task2-attesta-trigger lesson).
3. **Anchoring key and log key wiring:** the platform anchoring credential is a `SigningAdapter` credential for `ATTESTA_PLATFORM_TENANT_ID` (Task15f decision 1), resolved from `ATTESTA_ANCHOR_CREDENTIAL_ID` through a small `anchorSignerFromEnv(env)` that, outside production, builds a `LocalDevSigner` from `ATTESTA_DEV_ANCHOR_KEY_FILE`; in production it refuses to start until Task15l supplies the platform resolver (fail closed, clear message). Rekor/TSA URLs, the pinned log key (`ATTESTA_REKOR_LOG_KEY_FILE`), `logIndexOffsets` (JSON) and TSA trust anchors (`ATTESTA_TSA_ANCHORS_FILE`) come from env; nothing secret is logged.
4. **CLI** `npm run attesta:anchor -w apps/api` runs one pass (`--loop` with a 5-minute sleep for local use; `--tenant <uuid>`; `--max-batch`); prints counts and codes only. Production scheduling is Task14's.
5. **Verify report:** extend `verify-chain.ts` (additively, report version unchanged unless a field is added; if one is, bump `CHAIN_REPORT_VERSION` and say why): an optional `anchors` option (`{ rekorLogKey, rekorLogIndexOffsets?, anchorKeysSpkiDer[], tsaAnchors, windowMs = 3_600_000, now }`). With it, every record gets an `anchor_status` (`anchored` both types · `pending` within the window · `missing` beyond it), each stored anchor row is checked with `verifyStoredAnchor`, and breaks are `ATTESTA_VERIFY_MERKLE_PROOF_INVALID`, `ATTESTA_VERIFY_ANCHOR_INVALID`, `ATTESTA_VERIFY_ANCHOR_MISSING`. A `not_checkable` result (missing key material) makes the report `NOT_CHECKABLE`, never `ok`. TSA revocation `unknown` is a **warning** in the report, not a break (Task15f decision 3). Without the option, behaviour is unchanged and the report says anchors were not checked.
